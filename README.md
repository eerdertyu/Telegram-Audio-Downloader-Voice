# Telegram Audio Downloader Voice

Бесплатный Telegram-бот, который принимает голосовые сообщения и возвращает MP3-файлы с заданными именами.

## Возможности

- `/name кефир` — имена файлов будут `кефир 1.mp3`, `кефир 2.mp3` и т. д.
- `/name` — сбросить название; имена будут `1.mp3`, `2.mp3` и т. д.
- Отправка до 10 голосовых подряд с автоматической обработкой после паузы.
- `/done` — запустить обработку немедленно.
- `/cancel` — удалить текущую необработанную партию.
- Исходный звук не ускоряется и не замедляется: конвертация сохраняет длительность.

Название действует, пока пользователь его не изменит или не сбросит.

## Локальный запуск

Нужны Python 3.12+ и FFmpeg.

```bash
pip install -r requirements.txt
```

Linux/macOS:
```bash
export BOT_TOKEN="токен_от_BotFather"
python main.py
```

Windows PowerShell:
```powershell
$env:BOT_TOKEN="токен_от_BotFather"
python main.py
```

## Деплой на Railway

1. Создай бота через [@BotFather](https://t.me/BotFather) и скопируй токен.
2. На Railway создай новый проект из этого публичного GitHub-репозитория.
3. В Variables добавь переменную `BOT_TOKEN` со значением токена.
4. Railway автоматически использует Dockerfile. Запусти Deploy.
5. Убедись, что сервис работает. Дополнительный домен и база данных не нужны.

Не публикуй токен в GitHub и не вставляй его в код.

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---:|---|
| `BOT_TOKEN` | — | Обязательный токен Telegram-бота |
| `BATCH_IDLE_SECONDS` | `8` | Сколько секунд ждать после последнего голосового перед обработкой |
| `LOG_LEVEL` | `INFO` | Уровень логирования |

## Как работает партия

Бот собирает голосовые отдельно для каждого чата. После 8 секунд без новых голосовых он начинает конвертацию. Партия из 10 файлов обрабатывается сразу. Если нужно отправить меньше 10 файлов и не ждать таймер, отправь `/done`.

## Ограничения Telegram

Бот использует стандартный облачный Telegram Bot API. Скачивание входящего файла ограничено возможностями Telegram Bot API (обычно до 20 МБ на файл). Для работы нужен постоянно запущенный Railway service; не включай для него serverless sleep.
